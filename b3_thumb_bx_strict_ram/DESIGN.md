# B3：收紧 BX 快捷路径的目标地址

本实验接续 B2 的独立复核，仅在副本里收紧目标地址。R1 仍为正式基线，原 B2、独立复核报告均保持不变。

## 动机与范围

B2 把 `0x02000000..0x03FFFFFF` 整体作为可能的普通内存目标。这个范围在 DS 运行环境中还包含 GBR3 私有内存及线性 ROM 搬移地址，不能仅凭 GBA 总线地址分类就启用特殊处理。

B3 只对以下三段原始目标地址启用快捷路径：

| 地址段 | 下限（含） | 上限（不含） |
|---|---|---|
| 标准 EWRAM 区 | `0x02000000` | `0x02040000` |
| 标准 IWRAM 区 | `0x03000000` | `0x03008000` |
| 低 2MB ROM | `0x08000000` | `0x08200000` |

其他地址全部回到 R1 原有映射/执行路径。这不宣称 GBA 内存镜像地址非法，也不改变游戏对它们的访问语义；仅表示这些地址不在本优化的白名单内。

B3 没有加入低 ROM→DS 地址直接换算优化，没有更改存档、声音、SD、JIT/MSR/IRQ 处理逻辑，也没有新增 RAM 状态或堆分配。

## 源码差异

相对 B2 仅 `CachedThumbBx.s` 中的目标范围判断和对应注释改变。函数入口、取缓存字节、BX 编码识别、目标寄存器取值、保存帧/SPSR 更新、回退方式均不变。

`B2_TO_B3.patch` 是相对 B2 的差异；`SOURCE.patch` 是相对 R1 的完整差异，仍只涉及两个源文件。

判断低 ROM 放在前面。RAM 采用无符号区间检查：`target-base < size`。这三段范围均不跨越 32 位地址回绕，减法下溢的地址不会通过检查。区间只看原始目标地址，随后仍按原 BX 规则处理 ARM/Thumb 对齐和 SPSR.T。

## 指令级验证

使用已有私有 melonDS ARM946 解释器，执行本次实际链接的 196 字节函数及常量池。与原生 Thumb BX 对比，并验证回退不改变原保存帧/SPSR。

- 保留 B2 的全部原生执行/回退测试。
- 新增三段区间的下限前后、上限前后及每种字节对齐；覆盖四个目标寄存器、四种取指位置及不同状态标志。
- 新增 DS 私有内存、堆、数据缓存、`0x022xxxxx` 搬移区和范围外地址的明确拒绝测试。
- 总计 1,388 组原生等价检查、770 组回退检查通过。其中新增边界矩阵为 576 组放行、480 组回退。
- 65,536 个半字的编码集合检查保持只允许 `BX r0-r3` 四种编码。这不是对全部半字逐条执行 CPU 测试。

成功路径仍只写已有异常帧里的重试 PC；新函数本身不扩栈、不写 MPU、指令缓存标签、游戏 RAM、存档或 SD。

指令测试是隔离环境，不包括真实 IRQ 注入和硬件 MPU/缓存时序；完整游戏回放与实机测试仍不可替代。

## 布局

ARM9 初始化映像为 131,536 字节，其中功能复制长度 131,308 字节。继续保留既有 228 字节诊断尾部省略策略。

ITCM 末端 `0x7FD8`；VRAM BSS 末端 `0x0681FF0C`。EWRAM/DTCM、堆、数据缓存及缓存指针表地址保持 R1/B2 原状。新 helper 长度为 196 字节；相对 B2 的最终初始化映像只增加 8 字节，链接对齐吸收了部分差异。

ARM7 NDS 段要求逐字节等于 R1。

## 独立复核报告的两处说明

1. 关闭 JIT 仍会经过原生 BX，B2 的该对照共 48,292 次快捷处理，首次翻卡窗口为 7,080 次。因此 38→37 模型帧表示该场景净结果未变慢，不能隔离出纯回退检查的成本。独立报告正文 §4.2 已说明这一点，不能把摘要解释为“不走快捷路径”。其他游戏的回退占比及净开销仍待测试。
2. 独立报告哈希表列的是另一个 `cn113/BPEJ00.pre`，但实际 `launch.json` 和脚本使用 `cn113/BPEJ00_native16.pre`，其 SHA256 为 `17b92398e7c236cfd2005c26383204017a7e59ac1e8751b4a6fe1b5bebea2602`。B3 延续实际回放输入，并将全部实际文件及哈希写入 `INPUTS.json`。这属于报告表格的命名差异，未推翻已复现的结果。
