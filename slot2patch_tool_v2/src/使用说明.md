# frlg_slot2patch_tool v2 使用说明（含 LR 深度扫描）

> 差分格式与 PatchToolForGbaR3 作者：**卧看微尘（Wokann）**。本工具只是在卧看 PatchTool 基础上做的封装、扫描与打包，不是自研补丁格式。公开完整 GBR3 实机教程前请先征得卧看同意。
> 本包**不含**任何 BIOS、ROM、NDS 文件；请自备。不宣称 GBR3 已正式支持任何 ROM。

## 为什么要深度扫描

GBARunner3 把低区 ROM 映射在 0x022xxxxx 运行，函数里拿到的 LR（返回地址）也是 0x022xxxxx。
汉化 ROM 里如果有代码用 LR 去**比较、查表或判断范围**（例如“从哪个调用者进来就走哪条分支”），在实机上会对不上 0x08xxxxxx 的表，导致文字错位、卡死等。
深度扫描会找出这类代码，并可自动插入换算：`若 (lr-0x02200000)>>21==0 则 +0x05E00000`。

## 用法（界面）

1. 双击 `打开界面.command`（Mac）或 `打开界面.bat`（Windows），或运行 `python3 gui_slot2patch.py`。
2. 选好原版 ROM 和汉化 ROM，点 **生成**。生成前会自动深度扫描（通常几秒）：
   - 无高／中风险：直接生成 slot2patch ZIP。
   - 有高／中风险：弹出一个窗口，上面列表列出问题（风险、地址、说明），下面三个按钮 **修复**／**不修复（直接生成）**／**取消**。
   - 扫描失败：询问是否跳过扫描直接生成。
3. 列表颜色：
   - 红色 **高**：在用（有 BL／指针跳转调用），且 LR 未换算 → 默认勾选
   - 橙色 **中**：可疑，需判断（例如 LR 由调用者经栈传入）
   - 蓝色 **低**：没找到调用者或像误报
   - 绿色 **已修**：已有换算，无需处理
   - “能否自动修”为 **需人工** 的条目不能勾选；点“修”一列或按空格切换勾选
4. 点 **修复**：窗口关闭，回到主界面后台修复并生成 slot2patch ZIP。
5. 完成后主界面上方用绿色大字显示「已生成（修复了 N 处）」和 ZIP 路径；点「打开所在文件夹」可直接找到 ZIP。

### 输出目录里有什么

- 默认**只留 slot2patch ZIP**（输出目录留空时放在汉化 ROM 同目录）。stage／verify_apply.gba 等中间文件都在临时工作目录里生成，成功或失败后都会自动删除；不会删除你原有的任何文件（同名 ZIP 会被新生成的覆盖）。
- 勾选「同时导出 BPS 和报告」时，额外导出对汉化 ROM 的 BPS、中文报告，以及修复后 ROM（仅本地自测用，请分发 BPS／ZIP）。

## 用法（命令行）

```
python3 lr_scan.py --rom 汉化.gba --orig 原版.gba --scan --json
python3 lr_scan.py --rom 汉化.gba --orig 原版.gba --fix-high --out 输出目录
python3 lr_scan.py --rom 汉化.gba --orig 原版.gba --fix 1,3 --slot2patch --out 输出目录
```

`--configs DIR` 指定 `_gba/configs`；不给时自动使用本目录的 `_gba/configs/`，整个打进 ZIP。
退出码 2 表示有条目无法自动修。

## 修复方式

- 在原位置写 `ldr rX,=跳板; bx rX`，跳板放在 ROM 末尾 0xFF 空白区。
- 跳板只用 ARMv4T 指令（无 Thumb-2）；标志位不需要保留时用 Thumb 跳板，需要保留时用 ARM `mrs/msr` 段。
- 被搬走的 ldr 字面量、b/bcc、bl 都会重新编码。
- 不改存档格式，不碰存档相关代码（检测到存档地址的条目只报不修）。

## 输出

- `*_GBR3LR修复.gba`：修复后的 ROM，**仅自用，勿传播**
- `*_GBR3LR修复.bps`：相对汉化 ROM 的补丁
- `*_LR扫描修复报告.md`：中文报告
- `slot2patch/*.zip`：GBR3 补丁包（含 `_gba/configs/`）

## 已知限制

- 只跟进一层被调函数；更深的比较可能漏报。
- 经栈传入的 LR 不追踪来源，只报“中”。
- ARM 状态下的命中不自动修；用到高寄存器（r8–r12）的需人工。
- 部分 `ldr rX,[sp,#n]` 条目（例如原版代码中的）可能是误报。
- 空闲空间取 ROM 末尾连续 0xFF；不够时会报错。
- 未在 GBR3 实机测试；修复后请先自行实机验证。
